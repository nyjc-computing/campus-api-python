# Circles authorization in flask_campus — 4-phase, cross-repo change

**Goal:** give consuming Flask apps a circles-backed admin gate (`OAuthLoginManager.circle_admin_required`), migrate campus-admin off its env-var `ADMINS` check, and add an upstream membership probe so client checks can't drift from server rules. Enforcement stays in campus.api; the decorator is view-level UX gating, fail-closed.

Sequencing matters because flask-campus pins the SDK by wheel URL: PRs merge independently, but **releases are cut between phases 2→3 and 3→4**.

---

## Phase 1 — campus.api: `GET /circles/<id>/members/<member_id>` probe
Repo: `~/nyjc-computing/campus` (branch off `weekly`: server contracts live there). Awt-registered worktree `feat/circles-member-probe`.

- `campus/api/resources/circle.py`: add a `get(circle_id, member_id)` to the members resource — returns the member's access value, or a not-found signal when absent.
- `campus/api/routes/circles.py`: new probe route (200 + access value; missing circle/member → the repo's existing not-found convention — 409 per current route docstrings; verify against neighbors when implementing). Ungated, consistent with `members.list` being read-open (the probe leaks nothing `members.list` doesn't).
- Tests: unit coverage on the resource method + contract tests for the route including negative cases (mirroring `tests/contract/api/test_api_circles.py`).
- Update `docs/circles-access-control.md` (membership API + later-refinements note).

## Phase 2 — campus-api-python: client method for the probe
Repo: `~/nyjc-computing/campus-api-python`, branch `feat/circle-members-get`.

- `campus_python/api/v1/circles.py`: `CircleMembers.get(member_id) -> int | None` (None when absent), docstring documenting probe semantics.
- Additions to `tests/unit/test_circles.py`.

## Phase 3 — flask-campus: the decorators (the core change)
Repo: clone `nyjc-computing/flask-campus` (not local yet), branch `feat/circle-required`, awt-registered.

- **New** `src/campus/flask_campus/circles.py` (module-private, not exported → interface manifest unchanged):
  - process-local TTL cache of `<resource>.admin` members dicts keyed by circle name (60s TTL, mirroring `UserCache`/`USER_CACHE_TTL_SECONDS` in `context.py`); one fetch serves all users.
  - membership resolution **as the user** via `campus.with_user_session()` → `api.v1.circles` probe (falls back to `list` + name-filter + `members.list` only if building against a pre-probe SDK; target is the probe).
  - fail-closed error mapping: missing role circle or absent member → deny; API/network failure → deny + log (503-flavored, never fail-open).
- `src/campus/flask_campus/login_manager.py`: two methods on `OAuthLoginManager`:
  - `circle_member_required(circle: str)` — membership in any named circle.
  - `circle_admin_required(resource: str)` — sugar for `<resource>.admin`.
  Both redirect signed-out users to login *inside* the wrapper (order-independent stacking with `login_required`), and abort 403 for authenticated non-members (no login redirect loop).
- **New** `tests/unit/flask_campus/test_circle_required.py` (mirrors `test_login_required.py` patterns: plain Flask app, stub `/login` rule, `SimpleNamespace` user, fake campus client whose `with_user_session()` yields canned circles): signed-out→302; member→view runs; non-member→403; missing circle→403; API error→fail-closed; cache hit on second request; positional/keyword arg forwarding.
- `CHANGELOG.md` entry + version bump per repo rule (additive → patch: 0.1.11 → 0.1.12). Run the boundary/interface suites to confirm the manifest needs no regen.

## Phase 4 — campus-admin migration
Repo: `~/nyjc-computing/campus-admin`, branch `feat/circles-admin`.

- `apps/admin/__init__.py`: delete the env-var `admin_required` closure; its views take `@login_manager.circle_member_required(admin_circle)` where `admin_circle` comes from a new `ADMIN_CIRCLE` env override, defaulting to the bootstrap's `campus-admin` sentinel circle (deployment-portal admin), not `circles.admin`.
- Update app tests; note the `ADMINS` env removal in the PR.

## Verification
- Each phase: run that repo's unit suite locally (unittest), match repo lint/type config (ruff/pyright in flask-campus), contract tests in phases 1–2 run against the in-repo fixtures.
- Phases 3–4 tests stub the client, so they don't need released wheels — only runtime deployment does. Call out required releases in each PR description.

## Conventions
- Every repo: `awt list --repo` first, worktree per repo, `awt register` immediately, heartbeat during long runs, `awt deregister --unlock` when done. Branch names follow each repo's `feat/...` convention. No merges to default branches without PR.

**Explicitly out of scope:** access-value tiers, transitive membership resolution, user-circle provisioning (all upstream open questions in the circles doc).
